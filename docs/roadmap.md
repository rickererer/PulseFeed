# Roadmap

PulseFeed 当前是一个覆盖 Feed 流、互动、账号、发布与监控的完整教学级后端。
本文档记录从当前状态走向生产级还欠缺的能力，按里程碑拆分，供后续迭代规划。

已完成并持续迭代的工程化内容见 [CHANGELOG.md](../CHANGELOG.md)，架构设计见
[architecture.md](architecture.md)。

## 当前基线（2026-09）

- **功能**：时间线/热榜/关注三路 Feed（推拉混合分发）、点赞/收藏/评论（异步落库）、
  JWT 账号、视频发布、曝光上报、站内信、播放配置与 QoS
- **工程**：CI（vet/测试/覆盖率门槛/module 卫生）、Makefile、vitest、Docker Compose 一键启动
- **可观测**：Prometheus 指标（Feed 耗时、缓存命中、worker 任务）、Grafana 面板
- **已知边界**：测试覆盖率以接口与领域层为主，infra 持久化层依赖真实 MySQL/Redis 未覆盖

## M5 内容安全与审核

上线真实用户内容前必须补齐：

- [ ] 评论/标题/简介的内容安全接入（机审 API + 敏感词库）
- [ ] 审核后台最小闭环：待审队列、通过/拒绝、申诉处理
- [ ] 违规处置链路：内容下架、账号禁言/封禁（复用现有 `status` 字段扩展）
- [ ] 举报入口与处理流程

## M6 运营支撑

- [ ] 运营后台：视频/用户/互动数据检索与人工干预（下架、置顶、加热）
- [ ] 运营数据看板：DAU、发布量、互动率、Feed 点击率（复用现有 Prometheus 指标扩展业务维度）
- [ ] 推荐策略灰度：按用户分桶切换 Feed 策略，对比留存与互动指标
- [ ] 消息推送通道扩展（当前仅站内信，接入订阅消息/邮件）

## M7 治理与规模化

- [ ] 接口限流与防刷（登录、注册、互动写接口）
- [ ] infra 持久化层测试补齐（仓储层单测 + testcontainers），抬升 CI 覆盖率门槛
- [ ] 日志结构化（JSON 格式 + trace id 贯穿 handler → service → worker）
- [ ] 配置密钥外部化（环境变量注入，见 #29 密钥管理说明）
- [ ] 压测常态化：fanout 写放大对比（全推 vs 推拉混合）纳入回归
- [ ] 数据库迁移工具化（当前 AutoMigrate 适合启动，生产需要版本化迁移）

## 维护中的方向

以下能力已具备基础，持续优化：

- 覆盖率与测试深度（CI 已设防退化门槛）
- 缓存策略（页缓存/卡片缓存/计数分片已覆盖，继续补充降级路径测试）
- 文档（architecture / engineering / optimization 随实现同步更新）
